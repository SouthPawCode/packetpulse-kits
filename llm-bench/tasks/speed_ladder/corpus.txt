A managed switch keeps a forwarding table that maps each MAC address it has seen to the port it was learned on. When a frame arrives for an address the switch knows, it is sent out of exactly one port. When the address is unknown, the frame is flooded to every port in the same VLAN except the one it came in on. Entries age out after a few minutes of silence, which is why a device that moves between ports can appear to vanish for a moment before traffic finds it again.
Spanning tree exists to stop loops. Switches elect a root bridge, every other switch picks the lowest-cost path to it, and redundant links are placed in a blocking state until a primary path fails. Rapid spanning tree shortens the recovery from tens of seconds to a few seconds. A topology change notification makes every switch flush its forwarding table, which is a common reason for a brief burst of flooding after an uplink flaps.
A reverse proxy terminates TLS for a service, forwards the request to a backend on a private address, and adds headers so the backend can see the original client address and scheme. WebSocket connections need the Upgrade and Connection headers passed through and a long read timeout, because the connection stays open for hours. Buffering large uploads to disk protects a slow backend, while a generous body size limit keeps legitimate file transfers from failing with a 413.
Ceph stores objects across many disks and keeps copies according to a placement rule. Monitors hold the cluster map, object storage daemons hold the data, and placement groups decide which daemons own which objects. When a daemon stops answering heartbeats, the monitors mark it down, and after a grace period the cluster starts recovering the missing copies elsewhere. Recovery competes with client traffic for network and disk bandwidth, so a flapping link can slow every virtual machine that uses the pool.
Inference speed on a local language model has two separate costs. Processing the prompt is parallel work that scales with the number of input tokens and is limited by compute. Generating the answer is sequential, one token at a time, and is limited mostly by memory bandwidth, because every token needs the whole set of weights read once. A long prompt therefore delays the first token, while the size of the model and the quantization decide how fast the tokens arrive afterwards.
A firewall policy is an ordered list, and the first rule that matches wins. Good policies start by allowing return traffic for connections that were already permitted, then place narrow exceptions above the broad denials they carve holes in, and finish with a default that blocks everything else between segments. Mistakes are usually ordering mistakes: a broad allow placed above a specific block quietly defeats it, and nothing in the logs complains.
